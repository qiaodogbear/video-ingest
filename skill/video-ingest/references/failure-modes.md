# 失败模式与三态判定

本文件在本流程遇到"拿不到内容"或"结果可疑"时阅读。

## 1. 字幕三态：为什么不能二值判断

**现象（实测）**：未登录状态下，对三条视频（含公认带 CC 字幕的 TED-Ed 投稿）执行

- `GET /x/player/wbi/v2?bvid=..&cid=..` → `data.subtitle.subtitles == []`
- `GET /x/player/v2?bvid=..&cid=..` → `subtitle.subtitles == []`
- `yt-dlp --list-subs` → 只有 `danmaku  xml`

三者一致返回空，**但其中至少一条确实存在字幕**。

**结论**：无 cookie 时的空列表无法区分

- 平台侧确实没有原语字幕
- 有字幕但需登录才可见

因此 `probe` 输出 `needs_auth_check` 而不是 `empty`。把这种情况写成"该视频没有字幕"是错误结论。

**处置**：要么提供 cookie 后重探（见 cookies.md），要么直接走 ASR 并在输出中写明"未确认平台侧是否存在字幕"。

## 2. danmaku 不是字幕

B 站提取器会把弹幕放进常规 `subtitles`：

```
[info] Available subtitles for BV1qNYC6eEMj:
Language Formats
danmaku  xml
```

`danmaku` 是弹幕轨，XML 格式，**不是口播字幕**。判定时必须排除，并且**不能**因此认为"有字幕"。

同时注意：解析器遇到 `.xml` 会直接拒绝（"XML 通常为弹幕"），这是有意的。

**实现坑（已修）**：`--list-subs` 的表头行形如 `[info] Available subtitles for ...`，本身以 `[` 开头。若先判断"以 `[` 开头就跳过"，就永远进不了表格，`danmaku_only` 会恒为 `false`。必须先判断表头。

## 3. 覆盖率不是"下载成功"

- 拿到完整字幕文件 ≠ 覆盖全部讲话。
- 字幕时间稀疏有正常原因（片头片尾、无声演示、纯展示），**不能**用"字幕总时长 ÷ 视频时长"当识别准确率。
- 只有本地 ASR 覆盖完整音频时长时，才可以主张 `supported`，并且仍要检查**解码时长与平台声称时长的偏差**（本工具用 5% 阈值）。

`full_video_coverage` 为 `uncertain`/`partial` 时，输出必须带警示（门禁 G1）。

## 4. ASR 的有损性

- 中文同音字错误会**看起来非常合理**，直接污染结论。改动词、否定词、数字的错误优先级最高——这些错了会反转整段结论。
- 做法：用简介/元信息里的专有名词逐个交叉校验；把确认的错字写成 `corrections.json` **重放**，而不是手工改文本。
- 无法确认的听音歧义**保留并标注**，不要补一个"听起来合理"的词。
- 校正写入独立层；原文层与 `corrections.json` 同时保留，便于回溯。

## 5. 分类要具体，不要吞成"空"

字幕为空必须区分以下原因，不能统一记成空列表：

`no_native_subtitle` / `translation_only` / `needs_login` / `network_error` / `rate_limited` / `api_changed` / `content_unavailable`

**鉴权失败 ≠ 没有字幕。** 可以在清单中记录"字幕鉴权失败、改用可访问音频"，但不能隐藏原因。

## 6. 环境坑

| 现象 | 原因 | 处置 |
|---|---|---|
| `TypeError: open() got an unexpected keyword argument 'metadata_errors'` | faster-whisper 1.2.x 调用 `av.open(..., metadata_errors=..)`，PyAV 19.x 不接受 | **不要**反复升降级 PyAV；自行用 PyAV 解码成 16k 单声道 float32 数组传入模型（本工具 `asr.py` 已如此实现） |
| 模型下载卡在 0 字节 | HuggingFace Xet 传输通道问题 | 设 `HF_HUB_DISABLE_XET=1` 后重试 |
| 无 ffmpeg | 并非所有路径都依赖它 | faster-whisper 走 PyAV，自带 FFmpeg 库；仅格式转换才需要系统 ffmpeg |
| 输出乱码 / 进度卡住 | 控制台编码 | 设 `PYTHONIOENCODING=utf-8`、`PYTHONUNBUFFERED=1` |
| Chrome cookie 库无法复制 | Chrome 正在运行，库被锁（yt-dlp#10927） | **不要**关闭浏览器加密、不要提权、不要混用 WSL 去"修复"；改用用户导出的 cookies.txt |

## 7. 画面帧配对的失败模式

### 7.1 按 cue.start 单点取帧基本不可用

实测（407s 教学视频，1016 个采样点）：按 `cue.start` 取帧，**83%** 落在画面
变化点 1s 内——也就是转场过程中，取到的基本是空画面或半透明残影。

画面变化后稳定下来所需时间：中位 **1.18s**，最大 **1.44s**。

### 7.2 不要用"cue.start + 固定偏移"

看到 1.18s 就想加 1.2s 偏移是很自然的，但那是**对单个视频转场时长的拟合**，
换个视频即失效。正确做法是**区间求交**：字幕区间 ∩ 画面曝光段区间，取
**曝光段中点**——对转场免疫，且恒在内容稳定区内。

### 7.3 不要把"交集中点"当取样点

早期实现按交集中点取样，结果：一张被 6 条字幕引用的幻灯片被提取 6 次，
浪费 6 倍视觉模型调用，且同一画面出现多个 frame_id，破坏"帧 ↔ 视觉状态"
的一一对应。**曝光段才是原子视觉单位**，同一段只取一帧。

实测修正后：85 个曝光段 → 70 帧，17 帧被多片段共享（最多 6 条字幕共用）。

### 7.4 用"距边界距离"判断短段中转场是无效判据

取样点固定在段中点，所以"距边界距离 / 段长"恒为 0.5，任何基于相对位置的
阈值都不会触发。第一版实现因此把 70 帧全部标成中转场，第二版又矫枉过正
把 102 帧全标成 ok。

正确判据是**段本身的时长**：`span < 0.6s` 整段视为过渡/闪烁。

### 7.5 blank 不能用"亮度低"判断

黑底白字的幻灯片亮度也很低（mean≈5），但 std≈40、edge≈5。只用亮度会把
教学视频里最常见的幻灯片判成空白并丢弃。`blank` 必须同时要求
**亮度极端 + 完全没有结构（std 与 edge 都极低）**。

### 7.6 mid_transition 是"建议复核"，不是"丢弃"

实测被判 `mid_transition` 的帧，全部来自 0.2–0.4s 的短曝光段，但**文字与
图表仍然完整可读**。丢弃它们会损失真实内容；正确做法是保留并标注。

### 7.7 孤儿曝光段最容易被忽略

没有被任何字幕引用的画面段（实测 15/85）往往正是**无口播的屏幕内容**——
提示词、图表、代码。这类内容恰恰是"必须看画面才能理解"的部分，必须单独
报告出来，而不是因为没字幕就跳过。

### 7.8 缩放会毁掉文字

1080p 的正文小字在缩到 960px 宽后仍可读，但再小就会糊。给视觉模型或 OCR 的
帧不要盲目缩放；需要读文字时用原始分辨率（`--scale 1.0`）。

## 8. 已知未验证项

诚实记录，避免把未测当已测：

- **带 cookie 的字幕正向路径未在本机实网验证过**（当时 Chrome/Edge 均在运行，cookie 库被锁，未取得凭证）。相关代码路径已实现并有单元测试，但缺实网证据。
- 多分P批处理未实现（只处理显式选中的单个分P）。
- 说话人分离未实现。
- **画面帧的提取已实网验证，但"视觉理解"未验证**：`frames` 只负责取帧与
  配对，帧内容的解读由 Agent 完成，本工具不涉及。
- 字幕轨与画面帧的 OCR 交叉校验未实现（当前靠 Agent 目视核对）。
- 弹幕内容未做分析（本工具只做口播字幕与 ASR）。
- 画面范围是"按曝光段取的代表帧"，**不是逐帧 OCR**：极快的闪屏（< 0.2s）
  可能被采样步长漏掉。
