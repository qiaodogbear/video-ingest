# 输出模板

按此结构写。可以裁剪，但**素材来源声明与诚实边界不可省**。

## 1. 素材来源声明（必写，放在最前）

交代清楚结论建立在什么材料上：

```
- 平台字幕（人工 / 自动）：<语言键>，文件 <source/...>
- 本地 ASR：模型 <model>，设备 <cpu/cuda>，语言检测 <x> (prob <p>)
- 元信息与简介：作为辅助，不视为全文
- 校正：应用 <n> 条，见 corrections.json（原文层未被覆盖）
- 覆盖判定：full_video_coverage = <supported/uncertain/partial>，依据 <...>
```

**简介 ≠ 视频口播。** 说明哪些内容来自简介，不要混在一起。

## 2. 元信息表

标题、UP 主、时长、链接、发布时间、关键数据（播放/点赞等）。多 P 视频注明分P。

## 3. 作者内容总结

只依据原始材料。按视频自身的组织方式复述（阶段、章节、要点）。

- 保留关键数字、专有名词、方法名。
- 重要结论带片段证据，形如 `【seg-000012 / 00:42】`。
- 不补写视频没说的内容；不确定处标 `（听音不确定）`。

## 4. 方法论解析

与内容总结分开写。按固定维度整理：

| 维度 | 内容 |
|---|---|
| 阶段 | 流程的第几步 / 哪个环节 |
| 输入 | 需要什么材料 |
| AI 任务 | 交给模型做什么 |
| 人类任务 | 人必须自己做判断的部分 |
| 产物 | 产出什么 |
| 验证方式 | 怎么知道这一步做对了 |

**明确区分**：哪些是作者明确提出的，哪些是你作为解析者重组的。重组部分要标注。

## 5. 迁移建议（可选，标明是推导）

面向用户科研/课程学习的具体建议。这是**你的推导**，不要写成视频原话，也不要伪装成作者观点。

## 6. 待核查项

- 原文不清或转写疑似有误的术语
- **只在屏幕展示、口播未提的内容**：必须来自帧提取并引用 `frame_id`；
  帧里没读到的，记 `未获得画面内容`，**不得凭字幕猜**
- 视频未提供证据的断言
- 需要外部核验的事实（另列来源链接，与视频内容分开）

## 6b. 画面证据（抽取了帧时）

单独一节，把画面承载的信息与口播信息分开。每条视觉结论必须可定位：

```
- 【frame-run-0005-11933 / t=11.93s / 曝光段 9.63–14.23s】屏幕上是一张三段式对照表，
  左列"线性"、右列"复利"，与 seg-000002 口播的"这笔账"对应。
- 孤儿段 run-0001（0.0–3.8s）无对应字幕：片头标题卡，含栏目名"AI LEARNING LOOP"。
- **未获得画面内容**：口播提到"提示词如下"，但在 seg-000030–000033 的帧中未能读到
  完整提示词（画面为滚动文本，status=high_change）。此处不作推测。
```

标注帧状态的含义：`mid_transition` 的帧可以引用，但要说明"曝光段很短，可能含
弹入残留"；`blank` 不要引用；`high_change` 要说明单帧可能不代表整段。

## 7. 诚实边界（必写）

明确列出没拿到的信息，以及它对结论的影响：

```
- 未提供 cookie，无法确认平台侧是否存在字幕轨，本次内容全部来自本地 ASR
- verification_status = unreviewed：未做抽样比对，不声称逐字准确
- 未抽取画面帧 / 已抽取 N 帧但未覆盖全部曝光段，屏幕内容只在已抽帧范围内
- 某段音频无声 / 某处接口 403 等具体情况
```

## 8. 产物路径

给出 `job_dir` 下关键文件的真实路径，便于用户自行核对原文：

`transcript.txt`（原始全文）、`transcript.readable.md`（校正稿，若有）、
`chunks/index.json`（覆盖清单）、`frames.index.json` 与 `visual-index.md`
（画面证据，若抽取）、`manifest.json`（证据记录）。
